# Аудит флоу Postshop — 05.10.2026

Проверка заказов, возвратов, складов FBS/FBO и отображения во всех частях:
бэкенд, админка, витрина (покупатель и кабинет продавца), мобильное приложение.
Всё найдено чтением кода. Отметка `[x]` — исправлено.

## Бэкенд

- [x] B1. Владелец снимает блокировку, поставленную сотрудником, — и с магазина
  (`shop_bases.py` unblock), и с товара (`products.py` unblock). Права
  `SHOP_BASES_BLOCK` / `PRODUCTS_BLOCK` есть у каждого пользователя, проверка —
  только «свой магазин». Нужно помнить, кто заблокировал, и не давать владельцу
  снимать блок сотрудника.
- [x] B2. Блокировка товара сотрудником не уведомляет владельца (у магазина
  уведомление есть).
- [x] B3. Закрытие/блокировка магазина не учитывает открытые заказы, незакрытые
  возвраты и остаток FBO. Минимум — отказ владельцу закрыть магазин с открытыми
  заказами; сотруднику — предупреждение.
  Сделано: владельцу 409 при открытых заказах и незакрытых возвратах; сотрудник закрывает всегда.
- [x] B4. `order.comment` хранит и комментарий покупателя, и комментарий админа,
  и «Отменён покупателем: …» — последующая запись затирает предыдущую. Нужно
  отдельное поле для решения платформы.
  Сделано: новое поле `orders.status_comment`; старые отметки отмены перенесены миграцией.
- [x] B5. Из `ready_to_take` нельзя перейти в `rejected` — собранный заказ не
  отменить.
- [x] B6. Возврат можно оформить на товар из отклонённой части заказа; у FBS при
  получении остаток растёт из ничего.
- [x] B7. Отказ админом (глобальный `rejected`) не закрывает части заказа и не
  уведомляет магазины.
  Сделано: магазинам уходит `order_cancelled` с причиной. Статусы частей не меняются ни при
  отказе платформы, ни при отмене покупателем — иначе это считалось отказом магазина в его статистике.
- [x] B8. Единица измерения в приёмке и в движениях FBS/FBO не сверяется с
  единицей товара — баланс складывает разные единицы.
  Сделано: также запрещена смена единицы у товара, по которому уже есть движения или заказы.
- [x] B9. Ручное FBO-списание (`write_off`, `return_to_shop`) не учитывает резерв
  открытых заказов — при `completed` остаток уходит в минус.
- [x] B10. Незакрытые возвраты (`approved`, не получены) не блокируют смену типа
  склада.
- [x] B11. При `FBO_ENABLED=false` FBO-возврат помечается `restocked=true`, хотя в
  журнал ничего не пишется.
- [x] B12. При одобрении возврата магазину уходит `return_received`, хотя товар
  ещё не получен; при получении никого не уведомляют.
  Сделано: покупателю `return_completed` при получении. `return_received` при одобрении оставлен —
  его текст на фронтах уже про «товар едет к вам».

## Админка

- [ ] A1. (бэкенд готов: `q`, `fbo_attention`) Список заказов: `limit: 200`, без страниц и фильтра статуса, поиск только
  по загруженному. То же (до 500) у возвратов, приёмок, магазинов, модерации.
- [ ] A2. Нет «Отклонить» в статусах «Готов к выдаче» и «В доставке».
- [ ] A3. Отклонение заказа без причины (бэкенд принимает `comment`).
- [ ] A4. (бэкенд готов: `GET /orders/fbo/attention-count`) Нет счётчика/фильтра FBO-частей, ждущих сборки сотрудником.
- [ ] A5. В деталях заказа товары отказавшегося магазина не выделены.
- [ ] A6. (бэкенд готов: `PATCH /stock-receipts/{id}/items/{item_id}`) Приёмку можно только подтвердить: нельзя отменить, поправить количество;
  «отменена» и «черновик» — один вид бейджа.
- [ ] A7. Склад: только остатки — нет истории, списания брака, возврата магазину.
- [ ] A8. В карточке магазина нет его заказов, возвратов, остатков.
- [ ] A9. Нет статуса оплаты заказа (требует бизнес-решения).

## Витрина — покупатель

- [ ] C1. Итог заказа и цена в карточке — все товары + доставка, а не
  `effective_total`: при отказе магазина сумма завышена.
- [ ] C2. Не видно, какой магазин отказался и почему (`order_shops[].status`,
  `comment`).
- [ ] C3. Названия магазинов из справочника с лимитом — «Магазин без названия»;
  данные уже есть в `order_shops[].shop`.
- [ ] C4. Кнопка «Вернуть» у товаров отклонённого магазина.
- [ ] C5. После одобрения возврата нет инструкции и статуса получения
  (`received_at`, `restocked`).
- [ ] C6. Заказ с доставкой в «Ожидает» не предупреждает, что доставка добавится.
- [ ] C7. Отмена заказа без причины (бэкенд принимает `reason`).
- [ ] C8. Название товара — `translations[0]`, а не на языке интерфейса.

## Кабинет продавца (веб и приложение)

- [ ] S1. Отказ от заказа без причины — покупатель получает уведомление с пустой
  причиной.
- [ ] S2. Пересчёт FBS сравнивает с «доступно» (за вычетом резерва), а не с полкой.
  Показывать резерв отдельно (требует решения, что считать полкой).
- [ ] S3. Нет истории движений товара (`GET /stock-operations/{product_id}` не
  используется).
- [ ] S4. В «Комментарии» заказа продавец видит комментарий админа или отметку
  отмены вместо слов покупателя (следствие B4).
- [ ] S5. FBO-продавец не может попросить вернуть товар со склада и не видит
  списаний.

## Мобильное приложение — покупатель

- [ ] M1. Товары отказавшегося магазина показаны строкой «Скидка:».
- [ ] M2. Нет списка своих возвратов и отзыва заявки.
- [ ] M3. `OrderTotalFooter` считает «скидку» вместе с доставкой (сейчас
  используется только у продавца, где разницы нет).

## Известное, вне правок

- Части заказов, отменённых покупателем до этих правок, остались в статусе `rejected` и
  попадают в статистику отказов магазина.

## Требуют бизнес-решения

- Срок на возврат.
- Сумма к возврату; уменьшать ли выручку/топ на возвращённое.
- Возврат остатка покупки после одобренного возврата (сейчас нельзя).
- Бракованный FBO-возврат: куда девается, уведомлять ли магазин.
- Физическая логистика возврата: кто забирает, куда несёт покупатель.
- Согласие покупателя с ценой доставки до одобрения.
- Статус оплаты заказа.
