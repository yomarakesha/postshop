# Ручная проверка Postshop перед продакшном

План для прогона руками после правок аудита 05.10–06.10.2026 (`docs/audit-2026-10-05.md`).
Идём сверху вниз: каждый следующий раздел использует данные предыдущего.
Отмечайте `[x]`, при расхождении записывайте номер шага и что увидели.

Коды в скобках (B4, D2…) — пункты чек-листа аудита, которые проверяет шаг.

## 0. Подготовка

### 0.1. Окружение

- [ ] 0.1.1. Свежая база (не рабочая!). Из `backend/`:

- [ ] 0.1.4. Открыть `http://localhost:8000/docs` — страница открывается, в списке есть разделы Withdrawals и Orders.

## 2. Товары, модерация, блокировки

- [ ] 2.1. Каждый продавец создаёт по 2 товара в «шт» с ценой (например, 100 и 50 TMT).
- [ ] 2.2. Админка → «Модерация товаров»: 4 товара, постранично (A1). Одобрить все — продавцам пришло «Товар прошёл проверку».
- [ ] 2.3. **Блок сотрудником (B1, B2):**
  - админка → магазин FBS → товар → «Заблокировать»;
  - продавцу пришло «Платформа сняла товар с продажи»;
  - в «Моих товарах» вместо кнопки «Вернуть в продажу» — надпись «Снят с продажи платформой» (веб и приложение).
- [ ] 2.4. Через API (`/docs`) от продавца: `PATCH /products/{id}/unblock` → **403**. Админ разблокирует — товар снова в продаже.
- [ ] 2.5. **Обход блока:**
  - продавец сам снимает товар с продажи, потом админ его блокирует → **200**;
  - продавец пытается вернуть → **403**;
  - админ разблокирует.
- [ ] 2.6. Продавец сам снимает и возвращает свой товар — работает без ограничений.

- [ ] 4.2. Админка → «Приёмка товара»: черновик виден, бейдж жёлтый, в меню счётчик (A1, A6).

- [ ] 4.4. «Подтвердить приём».

- [ ] 4.7. «Списать» у D → 1 → на складе 7.

## 5. Покупка

- [ ] 5.1. Покупатель: в корзину товар A (FBS) × 2 и товар C (FBO) × 3.
- [ ] 5.2. Оформить с **доставкой по адресу**, комментарий «позвонить за час».
- [ ] 5.3. В «Моих заказах»:
  - статус «Ожидает»;
  - строка доставки: «Цену назначит оператор при подтверждении» (C6);
  - итог = только товары: 2×100 + 3×(цена C).
- [ ] 5.4. Магазины видны по названиям, с логотипами (C3).
- [ ] 5.5. Оформить ещё один заказ с **самовывозом** (товар A × 1) — пригодится для отмены.
- [ ] 5.6. Пустая корзина → оформить нельзя. Товар, которого нет в наличии, → ошибка «недостаточно».

## 6. Обработка заказа

### 6.1. Оператор подтверждает (D6)

- [ ] 6.1.1. Админка → «Заказы»:
  - в меню счётчик новых заказов;
  - в списке колонки «К оплате» и «Оплата» — «Не оплачен» (A1, D2).
- [ ] 6.1.2. Поиск по номеру заказа и по части телефона покупателя находит заказ (A1).
- [ ] 6.1.3. Фильтры по статусу и «Не оплачены» работают.
- [ ] 6.1.4. Открыть заказ с доставкой → цена доставки 20 → «Принять».
- [ ] 6.1.5. Покупателю пришло уведомление «Заказ подтверждён — цена доставки назначена», в тексте «Доставка 20 TMT, итого … TMT» (D6; веб и приложение).
- [ ] 6.1.6. Продавцу FBS пришло «Новый заказ» (и SMS, если включено). Продавцу FBO SMS не приходит.

### 6.2. Части заказа

- [ ] 6.2.1. В меню админки счётчик заказов увеличился на FBO-часть. Фильтр «Ждут склада Postshop» показывает этот заказ (A4).
- [ ] 6.2.2. У продавца FBO заказ без кнопок «Принять / Собран» — подпись «Заказ собирает склад Postshop».
- [ ] 6.2.3. **Отказ продавца с причиной (S1):** продавец FBS → «Отклонить» → причина «нет в наличии».
  - Покупателю пришло «Магазин отказался от части заказа» с этой причиной.
- [ ] 6.2.4. У покупателя:
  - у магазина FBS надпись «Магазин отказался: нет в наличии», его товары затенены;
  - строка «Отказ магазинов −200»;
  - итог = товары FBO + доставка;
  - в приложении — строка «Отказ магазинов», а не «Скидка» (C1, C2, M1).
- [ ] 6.2.5. В карточке заказа в админке товары FBS зачёркнуты, «К оплате» без них (A5).
- [ ] 6.2.6. Админка: FBO-часть → «Принять» → «Собран». Кнопка «Собран» у заказа стала активной.

## 9. Возвраты

Используем завершённый заказ из раздела 7.

- [ ] 9.1. У покупателя над товарами: «Вернуть можно до <дата через 14 дней>» (D3).
- [ ] 9.2. **Отклонённая часть (B6, C4):** у товаров отказавшегося магазина FBS нет кнопки «Вернуть».
  Через API (`POST /returns/`) на такую строку → **404**.
- [ ] 9.3. «Вернуть» у товара C → количество 1 → в окне «К возврату: <цена> TMT» (D4) → причина → отправить.
- [ ] 9.4. «Мои возвраты»: заявка «на рассмотрении» с суммой. «Отозвать» → заявка пропала. Подать снова.
  В приложении в заказе — кнопка «Отозвать» (M2).
- [ ] 9.5. Админка → «Возвраты»:
  - счётчик в меню, колонка «Сумма»;
  - «Одобрить»: покупателю пришло «Возврат подтверждён», продавцу — «Одобрен возврат — товар вернётся».
- [ ] 9.6. **Инструкция (D5):** у покупателя «Возврат одобрен. Принесите товар в любой пункт выдачи Postshop…» (веб и приложение).
- [ ] 9.7. **Получение FBO:**
  - продавец FBO в «Возвратах» видит «Возврат примет склад Postshop» без кнопок;
  - админка → «Получен — в продажу»;
  - на складе +1, в истории «Возврат от покупателя +1»;
  - покупателю пришло «Возврат получен, заявка закрыта», статус «Возврат завершён».
- [ ] 9.8. **Получение FBS:**
  - сделать завершённый заказ на товар FBS и возврат по нему;
  - продавец FBS: «Получен» → «Брак»;
  - остаток не изменился, статус «Получен, брак».
- [ ] 9.9. **Статистика (D4):** в кабинете продавца FBO (сводка, топ товаров) выручка и количество уменьшились на одобренный возврат.
  В «Что чинить» товар в списке возвращаемых.
- [ ] 9.10. **Срок (D3):**
  - в базе: `UPDATE orders SET completed_at = NOW() - INTERVAL 15 DAY WHERE id = <заказ>;`
  - у покупателя вместо «Вернуть» — «Срок возврата истёк»;
  - через API → **400** «return period … is over».
- [ ] 9.11. Отказ в возврате без причины невозможен. С причиной — покупатель видит её красным.

## 10. Вывоз товара со склада (S5)

- [ ] 10.1. Продавец FBO → «Склад» → «Остатки на складе» → «Забрать» у товара C.
  - Окно «Свободно: N»;
  - ввести больше N → ошибка;
  - ввести 2 и комментарий «заберу в пятницу» → «Заявка отправлена».
- [ ] 10.2. Вкладка «Вывоз со склада»: заявка «На рассмотрении». «Отозвать» → «Отозвана». Подать новую на 2.
- [ ] 10.3. Создать открытый заказ на весь свободный остаток товара D → «Забрать» у D недоступно (свободно 0).
- [ ] 10.4. Админка → «Вывоз товара»: счётчик в меню, заявка с составом и комментарием → «Выполнить».
  - Продавцу пришло «Склад выдал ваш товар» → ссылка ведёт на вкладку «Вывоз»;
  - на складе −2, в истории «Возврат вам со склада −2».
- [ ] 10.5. Ещё заявка → «Отклонить»: без причины не даёт; с причиной — продавец видит причину красным.
- [ ] 10.6. Магазин FBS: раздела «Склад» нет. Через API `POST /withdrawals/` с его товаром → **409**.
- [ ] 10.7. То же в приложении: «Склад» → «Забрать», вкладка «Вывоз», «Отозвать».

## 11. Закрытие магазина и смена типа склада

- [ ] 11.1. **Закрытие при открытой работе (B3):**
  - у продавца есть открытый заказ или нерассмотренный возврат;
  - «Закрыть магазин» → сообщение «Нельзя закрыть магазин, пока есть открытые заказы…» (веб и приложение).
- [ ] 11.2. Без открытых дел — закрывается. «Открыть магазин» — открывается.
- [ ] 11.3. **Закрытие платформой (B1):** админка → магазин → «Заблокировать».
  - Продавцу пришло «Магазин закрыт платформой»;
  - в кабинете «Магазин закрыт платформой… напишите в поддержку», кнопки «Открыть» нет;
  - через API `unblock` → **403**;
  - админ открывает.
- [ ] 11.4. **Смена типа склада (B10):** админка → магазин FBO → «Сменить на FBS»:
  - пока на складе есть товар или идёт возврат → отказ с причинами;
  - вывезти весь товар (раздел 10), закрыть возвраты → смена проходит.

## 13. Уведомления — сводка

Каждое уведомление проверить на витрине (колокольчик и страница) и в приложении: текст переведён, ссылка ведёт куда надо.

| Событие | Кому | Текст (ru) |
|---|---|---|
| Оператор подтвердил заказ с доставкой | Покупатель | «Заказ подтверждён — цена доставки назначена» + суммы |

| Товар заблокирован платформой | Продавец | «Платформа сняла товар с продажи» |
| Возврат одобрен / отклонён | Покупатель | «Возврат подтверждён» / «В возврате отказано» |
