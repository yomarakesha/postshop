FBO — Fulfillment by Operator (товар хранится на складе платформы)

Для хозяина магазина
===============================================================================
Роуты магазина
Метод   Роут                                    Действие
------  ------                                  ---------
POST    /stock-receipts/                        Создать заявку на поставку
POST    /stock-receipts/{id}/items              Добавить товар в заявку
DELETE  /stock-receipts/{id}/items/{item_id}    Убрать товар если ошибся
GET     /stock-receipts/{id}                    Посмотреть свою заявку
GET     /stock-receipts/                        Список своих заявок

Права: STOCK_RECEIPTS_CREATE, STOCK_RECEIPTS_READ

Последовательность:

1. Создать черновик заявки на поставку
   POST /stock-receipts/
   {
     "shop_id": 1,
     "warehouse_id": 2
   }
   Ответ → receipt.id (например 42). Запомнить его.

2. Добавить товары (по одному, можно несколько раз)
   POST /stock-receipts/42/items
   {
     "product_id": 10,
     "measure_unit_id": 1,
     "quantity": 50
   }
   Ответ возвращает item.id — понадобится для удаления.

3. Удалить позицию если ошиблись (опционально)
   DELETE /stock-receipts/42/items/7

4. Проверить итоговый список перед отправкой на склад
   GET /stock-receipts/42

   Заявка остаётся в статусе draft — магазин физически везёт товары на склад.
   Подтверждение делает только складчик после фактической приёмки.


Для складчика
===============================================================================
Роуты складчика
Метод   Роут                            Действие
------  ------                          ---------
GET     /stock-receipts/                Список входящих заявок (фильтр по складу и статусу)
GET     /stock-receipts/{id}            Посмотреть конкретную заявку
POST    /stock-receipts/{id}/confirm    Подтвердить приёмку товаров

Права: STOCK_RECEIPTS_READ, STOCK_RECEIPTS_CONFIRM

Последовательность:

1. Посмотреть все входящие заявки на свой склад
   GET /stock-receipts/?status=draft&warehouse_id=2&lang=ru

   Ответ — список заявок со статусом draft, отсортированных от новых к старым.
   Каждая заявка содержит название магазина, склада, список товаров с названиями и количеством.

   Пример ответа:
   [
     {
       "id": 42,
       "shop_id": 1,
       "warehouse_id": 2,
       "status": "draft",
       "created_at": "2026-05-28T08:30:00+00:00",
       "confirmed_at": null,
       "shop_name": "Магазин Али",
       "warehouse_name": "Склад Центральный",
       "items": [
         {
           "id": 7,
           "product_id": 10,
           "measure_unit": { "id": 1, "code": "шт" },
           "quantity": "50.000",
           "product_name": "Кроссовки Nike"
         }
       ]
     }
   ]

   Параметр lang — язык названий товаров (ru, en, tk и т.д.). По умолчанию ru.
   Если перевода на нужный язык нет — product_name будет null.

2. Открыть конкретную заявку для проверки
   GET /stock-receipts/42?lang=ru

   Сверить список товаров с тем что физически привёз магазин.
   Ответ аналогичен одному элементу из списка выше.

3. Подтвердить приёмку
   POST /stock-receipts/42/confirm

   После подтверждения:
   - receipt.status меняется на confirmed
   - confirmed_at заполняется текущим временем
   - Для каждого товара из заявки создаётся запись в warehouse_operations
     с operation_type = income
   - Добавлять или удалять позиции больше нельзя
   - Ответ возвращает итоговую заявку с теми же полями что и при просмотре

4. Проверить остаток на складе (опционально)
   GET /warehouse-operations/warehouse/2/product/10/balance
   Ответ → { "warehouse_id": 2, "product_id": 10, "balance": 50 }


Типы операций склада (warehouse_operations)
===============================================================================
Тип                     Знак    Когда создаётся
---                     ----    ---------------
income                  +       Товар принят от FBO-магазина (через confirm receipt)
return_from_customer    +       Покупатель вернул товар — ложится обратно на склад
sold                    -       Покупатель купил товар — платформа списывает со склада
return_to_shop          -       Платформа вернула нераспроданный товар магазину
write_off               -       Списание брака, порчи или утери на складе


FBS — Fulfillment by Seller (магазин управляет своим складом сам)

Все роуты для fbs в файле stock_operations.py

Типы операций магазина (stock_operations)
===============================================================================
Тип                     Знак    Когда создаётся
---                     ----    ---------------
income                  +       Магазин получил товар от поставщика
return_from_customer    +       Покупатель вернул товар магазину
sold                    -       Покупатель купил товар
return_to_supplier      -       Магазин вернул товар поставщику

Примечание: при возврате от покупателя создаются две отдельные операции:
  1. return_from_customer (+) — товар вернулся на остаток
  2. return_to_supplier   (-) — если магазин решил вернуть его поставщику
